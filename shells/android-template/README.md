# Android shell template

The Android native application template used by `wefter sync` to build Android applications.

When targeting Android, Wefter generates a disposable project in `.wefter/native/android` using this template as its foundation. Plugin source files are copied into the source tree, and build configuration files are populated with the dependencies and permissions declared in your plugins.

## Architecture

The shell is written in Kotlin and structured around a minimal native wrapper:

### Core components

- `MainActivity.kt`: The main entry point activity. Configures the Android `WebView`, attaches the JavaScript bridge interface, configures splash screen behavior, handles back button gestures, and routes lifecycle events.
- `WefterBridge.kt`: Implements the JavaScript interface exposed to the WebView (`window.AndroidBridge`). It receives raw calls from JavaScript, schedules them on an asynchronous coroutine dispatcher, and hands them to the dispatcher.
- `BridgeDispatcher.kt`: Manages plugin registration, coordinates call routing, handles event hook subscriptions, and executes JavaScript callbacks via `evaluateJavascript` on `window.__wefterNative`.
- `WefterPlugin.kt`: Abstract base class that all Android plugins extend. Provides access to the host `Activity`, application `Context`, lifecycle coroutine scope, and bridge emission helpers.
- `WefterAnnotations.kt`: Defines `@WefterMethod` and `@WefterHook` annotations. The code generator scans these annotations to construct dispatch tables.
- `WefterError.kt`: Standardized error container mapping native exceptions and error codes into bridge rejections.
- `GeneratedRegistry.kt`: Generated by `wefter sync`. Maps string plugin identifiers to plugin instances and provides static method dispatchers without reflection.

## Bridge communication flow

1. JavaScript calls `invokeNative(plugin, method, payload)`.
2. The WebView invokes the `@JavascriptInterface` method on `WefterBridge`.
3. The bridge parses the payload JSON and dispatches execution to a background worker thread.
4. `BridgeDispatcher` looks up the target plugin in `GeneratedRegistry`.
5. The plugin method executes, performing native work such as querying sensors or reading secure storage.
6. The plugin returns a result or throws an exception.
7. `BridgeDispatcher` packages the result as JSON and calls `window.__wefterNative.resolve(callId, data)` or `window.__wefterNative.reject(callId, error)` in the WebView.

## Gradle build configuration

The template uses Gradle Kotlin DSL (`build.gradle.kts`) with specific marker comments where `wefter sync` injects configuration:

- `WEFTER-SPLASH-CONFIG`: Configures splash duration, fade transition, and ready-signal wait states.
- `WEFTER-ORIENTATION-CONFIG`: Injects screen orientation locks.
- `WEFTER-ENV-CONFIG`: Configures environment-specific variables, package names, and app titles across product flavors (`development` and `production`).
- `WEFTER-PLUGIN-DEPS`: Appends Gradle dependencies declared by installed plugins.

Release signing can be configured using environment variables:

- `WEFTER_KEYSTORE_PATH`: Path to the `.keystore` or `.jks` file.
- `WEFTER_KEYSTORE_PASSWORD`: Keystore and key password.
- `WEFTER_KEY_ALIAS`: Keystore alias name.

## Requirements

- Android SDK with compileSdk 36 and minSdk 24
- JDK 17
- Android Gradle Plugin 8.9 or later
