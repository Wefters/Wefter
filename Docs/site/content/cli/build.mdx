---
title: wefter build
description: --release, --env, and what it actually requires before it'll run.
---

```bash
wefter build <platform> [projectDir] [--release] [--env <environment>]
```

| Argument/Option | Type | Default | Purpose |
| --- | --- | --- | --- |
| `platform` | positional, required | — | Target platform. Only `"android"` is accepted right now — anything else fails immediately with `Unsupported platform "<x>". Only "android" is supported right now.` |
| `projectDir` | positional, optional | current working directory | Project root. |
| `--release` | boolean flag | `false` | Build a signed release artifact instead of a debug one. |
| `--env <environment>` | string | `"development"` | Which entry under `config.environments` to build against. |

```bash
wefter build android
wefter build android --release --env production
```

## Requires an already-fresh sync — it does not sync for you

Before doing anything else, `build` checks that the project has already
been synced and that `wefter.config.json` hasn't changed since. If either
is untrue, it fails immediately without touching Gradle:

```
Project has never been synced. Run `wefter sync` first.
```

or

```
wefter.config.json has changed since the last `wefter sync`. Run `wefter sync` before building.
```

<Callout type="warn">
  This is a freshness *check*, not an implicit sync — `build` never
  regenerates the native project itself. If you've just edited config or
  a plugin, run [`wefter sync`](/cli/sync) first. [`wefter run`](/cli/run)
  has the exact same requirement.
</Callout>

## `--release` runs a security lint first

With `--release`, before invoking Gradle at all, `build` runs the same
release security lint [`wefter doctor
--release-readiness`](/cli/doctor#--release-readiness-additional-checks)
runs: the release build type's dev-server URL must be empty, no `.kt` file
may hardcode `setWebContentsDebuggingEnabled(true)` outside a debug gate,
the debug network security config must exist, and a `signing` block with
an existing keystore file must be present in config. Any failure here
stops the build before Gradle runs:

```
Release security check failed:
  - No release signing config found in wefter.config.json
```

Running `wefter doctor --release-readiness` beforehand catches this (and
the `WEFTER_KEYSTORE_PASSWORD` requirement below) without spending time on
a Gradle invocation first.

## What Gradle task actually runs

`build` invokes `./gradlew assemble<Env><BuildType>` inside the generated
(or ejected) native project — e.g. `--env production --release` runs
`assembleProductionRelease`; plain `wefter build android` runs
`assembleDevelopmentDebug`. For a release build, three environment
variables are set for that Gradle invocation:
`WEFTER_KEYSTORE_PATH`, `WEFTER_KEY_ALIAS`, and `WEFTER_KEYSTORE_PASSWORD`
(read from your shell/`.env` — build fails with `WEFTER_KEYSTORE_PASSWORD
not set...` if it's missing).

## Finding the APK afterward

The built artifact is read back from
`app/build/outputs/apk/<env>/<debug|release>/*.apk` inside the native
project. On success:

```
Built .wefter/native/android/app/build/outputs/apk/development/debug/app-development-debug.apk (18.4 MB)
Using 2 registered plugin(s): device-info, ping-test
```

If a plugin is declared in `config.plugins` but isn't actually resolvable
in `node_modules` right now, that's reported as a warning rather than a
failure, since the last successful sync may have run before the plugin
was removed:

```
Registered plugin(s) not found in node_modules: some-plugin. Run `wefter sync` to refresh the registry.
```

## Failure and exit codes

Any failure — unsupported platform, stale sync, failed release lint, or a
non-zero Gradle exit code — prints `Build failed: <reason>` and sets
`process.exitCode = 1`. Success sets `0`.
