```bash
wefter sync [projectDir] [--update-lock]
```

| Argument/Option | Type | Default | Purpose |
| --- | --- | --- | --- |
| `projectDir` | positional, optional | current working directory | Project root — the directory containing `wefter.config.json`. |
| `--update-lock` | boolean flag | `false` | Accept plugin versions that drifted from `wefter.lock.json` and re-lock them instead of failing. See [wefter.lock.json's role](/cli/lockfile-role). |

Reads `wefter.config.json`, resolves every declared plugin, and rebuilds
the entire native Android project from scratch. Doesn't compile Kotlin,
doesn't produce an APK, doesn't touch a device — that's what
[`build`](/cli/build) and [`run`](/cli/run) are for, and both call `sync`
first internally.

## Explicit-only — no auto-scan, stated plainly

`sync` resolves plugins by reading `config.plugins`, an array of package
names, and looking up exactly those names under `config.pluginsDir`
(`node_modules` by default). It never walks `node_modules` looking for
anything that resembles a plugin. A package sitting in `node_modules`,
even one your web app directly imports at runtime, contributes nothing —
no native code, no permissions, no Gradle dependency — unless its name is
in that array. See [Plugin Registry](/docs/plugin-registry) for the full
reasoning behind this.

## What it does, in the actual order it happens

1. **Resolve declared plugins.** Reads `plugin.json` for each name in
   `config.plugins` from `config.pluginsDir`. Names with no matching
   `plugin.json` are reported back as unresolved, not treated as a fatal
   error at this stage.
2. **Audit permissions.** Scans each resolved plugin's Kotlin source for a
   short list of sensitive API usages (`CameraX`, `LocationManager`) and
   fails the whole sync if one is used without its corresponding
   permission (`android.permission.CAMERA`,
   `android.permission.ACCESS_FINE_LOCATION`) declared in that plugin's
   `plugin.json`.
3. **Check lockfile drift.** Compares each resolved plugin's installed
   version against `wefter.lock.json`. Fails here (before touching
   anything else) unless `--update-lock` was passed. Full detail:
   [wefter.lock.json's role](/cli/lockfile-role).
4. **Validate every plugin directory.** Runs the same validation
   [`wefter plugin validate`](/cli/plugin-validate) runs, standalone,
   against each resolved plugin — malformed `@WefterMethod`/`@WefterHook`
   signatures, and `plugin.json`'s declared `methods`/`hooks` matching
   what's actually in the Kotlin source. Any failure here stops the sync.
5. **Recreate the native shell** (skipped if the project has been
   [ejected](/cli/eject)). Wipes and re-copies the entire
   `.wefter/native/android` directory from Wefter's shell template, except
   it deliberately preserves any `build/` and `.gradle/` directories it
   finds, so Gradle's own build cache survives a sync instead of forcing a
   full rebuild every time.
6. **Inject the Android namespace** into `build.gradle.kts` and rewrite
   every `package dev.wefter.bridge` declaration in the shell (and move
   the corresponding source tree) to your real namespace, derived from
   config as described in [wefter.config.json's role](/cli/config-role).
7. **Copy web assets** from `config.webDir` into the native project's
   asset folder — fails if that directory or its `index.html` doesn't
   exist. Also resets the release build type's dev-server URL field to
   empty (`run --watch` is what fills this in, and only for the debug
   build).
8. **Copy and weave plugin native source** — each resolved plugin's
   `android/*.kt` files get copied in and have their own `package
   dev.wefter.bridge` declarations rewritten to match, the same rewrite
   the shell itself goes through. This is why a plugin author never needs
   to know what namespace any given app will actually use.
9. **Merge Gradle dependencies, Android permissions, and ProGuard rules**
   from every resolved plugin's `plugin.json` into the generated
   `build.gradle.kts`, `AndroidManifest.xml`, and `proguard-rules.pro`,
   inside clearly marked generated blocks.
10. **Inject per-environment build config** for every entry under
    `config.environments`.
11. **Generate launcher icons**, only if `config.icon` is set — see
    [App Icon](/docs/app-icon) and [`wefter icon
    generate`](/cli/icon-generate).
12. **Resolve and copy the splash screen**, only if `config.splash` is set
    (and not `false`) — see [App Splash Screen](/docs/app-splash-screen)
    and [`wefter splash generate`](/cli/splash-generate).
13. **Generate the plugin registry** — a single `GeneratedRegistry.kt`
    written from every resolved plugin's extracted methods and hooks.
14. **Write `wefter.lock.json`** with the freshly resolved version and
    integrity hash of every plugin.
15. **Write the sync marker** — a hash of the current
    `wefter.config.json`, checked by [`build`](/cli/build) and
    [`run`](/cli/run) to refuse running against a stale sync.

## Not incremental

Every run rebuilds the generated registry, merged Gradle/manifest/ProGuard
blocks, and plugin source from your *current* config, from nothing. There
is no persistent, partially-updated state that can drift from what's
actually declared — the tradeoff is that `sync` always does the full
amount of work above, not a diff of what changed.

## Ejected projects: transactional

Once a project is [ejected](/cli/eject), `sync` still runs — it just skips
step 5 (recreating the shell) and step 6 (namespace rewrite), since
`android/` is yours to hand-edit at that point. Everything else still
happens, wrapped in a snapshot-and-restore: if any step throws, every file
`sync` would have touched (the generated registry, plugin source
directory, `build.gradle.kts`, the manifest, web assets, and
`proguard-rules.pro`) is restored to its pre-sync state rather than left
half-modified.

## Failure behavior

Any failure at any step aborts the whole run and prints:

```
Sync failed: <reason>
Fix the problem and run `wefter sync` again.
```

with `process.exitCode = 1`. Nothing partially succeeds silently.
